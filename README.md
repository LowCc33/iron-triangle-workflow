# 🚀 Iron Triangle Workflow - 铁三角多Agent协同开发工作流

## 🎯 项目定位

专为转行AI应用开发者设计的**全自动协同开发系统**，实现：
- 用户只负责提需求和验收，中间零思考、零记忆负担
- 多个AI Agent通过Git文件自动协作，100%可靠
- 彻底解决Agent记忆不可靠、消息丢包、状态不一致等行业痛点

## 🛠️ 核心模块

1. **watcher调度器**：每分钟轮询，自动检测新任务并分配
2. **规则注入引擎**：自动将总规则、代码规范注入每个任务最前端
3. **幂等性校验模块**：防止任务重复执行
4. **Git缓存修复机制**：解决WSL2跨系统文件缓存问题
5. **双轨兜底机制**：全自动 + 手动触发，永不掉线

## 📝 示例规则文件

### 【示例】多AI协作总规则（简化版）

```markdown
# 铁三角多AI协作总规则 V1.0（示例版）

## 核心原则
1. Git是唯一状态总线，所有状态必须落地成文件
2. 文件优先级 > AI记忆，规则冲突以文件为准
3. 每个任务只能被一个Agent认领，防止竞争
4. 任务完成必须生成回执，老大确认后才算闭环

## 工作流程
1. 老大在 pending/ 目录下放任务文件
2. watcher自动检测，分配给对应Agent
3. Agent认领后移到 running/，开始执行
4. 执行完成移到 done/，生成回执到 receipts/
5. 老大验收，不满意打回 rejected/，满意则闭环
```

### 【示例】代码开发规范（简化版）

```markdown
# 大将军代码开发规范 V1.0（示例版）

1. 禁止硬编码，所有参数全放 config.py
2. 强制三级中文注释，100%中文文档
3. 提交前必须自测通过，禁止提交部分代码
4. 禁止TODO，禁止无用导入
5. 异常路径必须有降级逻辑，不能直接崩溃
```

## 📌 与其他Agent框架的区别

- **不是玩具**：解决真实生产环境的痛点（WSL缓存、幂等性、状态不一致）
- **不是重型框架**：几百行代码，零依赖，可读性极强
- **不是聊天驱动**：纯文件驱动，100%可靠，不受聊天平台限制
- **不是黑盒**：所有逻辑透明，可定制可扩展
